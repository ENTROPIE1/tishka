# Тишка

Настольный помощник-ёжик: живёт в углу экрана, слушает голос, выполняет рутину через локальные модели и подключённые системы. Electron, TypeScript.

## Что нужно

- Windows 10 или 11.
- Node.js 22 или новее, Git.
- Доступ к шлюзу моделей (корпоративная сеть или VPN) и свой ключ шлюза.
- Для голоса — служба распознавания и служба синтеза: локально или на отдельной машине через туннель (раздел «Голос»).

## Запуск

```powershell
git clone https://github.com/ENTROPIE1/tishka.git
cd tishka
npm install
node node_modules\electron\install.js
npm run build:mcp
npm run dev
```

- `npm run build:mcp` собирает серверы подключений (Confluence, Exchange). Повторять после обновления кода серверов.
- `node node_modules\electron\install.js` доустанавливает сам Electron: новые версии npm не запускают установочные скрипты пакетов, и без этой команды будет ошибка «Electron failed to install correctly». Предупреждения npm про `allow-scripts` можно не трогать.
- Путь к каталогу проекта может содержать кириллицу; пути к программе и модели распознавания — нет.

Обновление: `git pull`, затем `npm install`, `npm run build:mcp`, `npm run dev`.

## Первая настройка

Пока ключ шлюза не задан, при запуске открывается основное окно на экране «Подключения». Слева — экраны.

1. **Подключения → модель.** Ввести свой ключ шлюза, сохранить. Точка внизу слева станет зелёной. Ключ хранится в зашифрованном виде в профиле пользователя и в репозиторий не попадает. Если шлюз моделей у вас свой, укажите здесь его адрес и имена моделей. Кнопка «Проверить» покажет, отвечает ли шлюз и какие модели он предлагает. Если шлюз понимает только формат OpenAI Responses, выберите «Responses» в поле «Формат запросов» — запросы пойдут на `/responses`.
2. **Подключения → «Добавить».** По желанию — Confluence (адрес вики и личный токен) и Exchange (адрес EWS, адрес OWA, логин, пароль). У каждого свои учётные данные.
3. **Голос.** См. ниже.

Когда ключ задан, ёжик становится основным местом общения: при следующем запуске основное окно не открывается, на экране сразу появляется ёжик со строкой ввода — пишите и говорите прямо ему. Основное окно можно открыть кнопкой «Настройки» у строки ввода ежа, левым щелчком по значку в области уведомлений (экран чата), повторным запуском приложения и пунктом «Открыть в чате» в карточке ежа.

Закрытие окна приложение не завершает; выход — «Выход» в значке.

Настройки, история, навыки и память лежат в `%APPDATA%\tishka`. Чтобы начать с чистого листа, закройте приложение и удалите этот каталог.

## Голос

Тишке нужны две службы на локальных адресах:

| Служба | Адрес | Что делает |
|---|---|---|
| Распознавание | `http://127.0.0.1:8178` | whisper.cpp (`whisper-server`) |
| Синтез | `http://127.0.0.1:8179` | `GET /health`, `POST /tts` c телом `{"text": "..."}` → `audio/wav` |

### Вариант А: службы на отдельной машине (туннель)

Службы работают на машине с видеокартой и слушают только свой `127.0.0.1`; с рабочего компьютера к ним ходят через туннель SSH.

1. Создать свой ключ (один раз):

   ```powershell
   ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\tishka_speech" -C "tishka-speech"
   ```

   На вопрос о парольной фразе можно нажать Enter.
2. Передать владельцу машины со службами **открытую** часть — содержимое файла `tishka_speech.pub` (одна строка). Закрытый файл `tishka_speech` никому не передаётся.
3. Владелец добавляет ключ у себя (см. «Добавить ключ участника»).
4. Запустить туннель и держать окно открытым:

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\speech-tunnel.ps1 -HostName <адрес машины> -User <пользователь> -Stt
   ```

   Без `-Stt` пробрасывается только синтез.
5. В приложении, экран «Голос»:
   - «Служба распознавания»: выбрать «Готовая служба по адресу», адрес `http://127.0.0.1:8178`, нажать «Проверить» — служба отвечает;
   - «Речь вслух»: включить «Говорить вслух», адрес `http://127.0.0.1:8179`, «Сказать пример».

Проверка туннеля без приложения:

```powershell
curl.exe --noproxy "*" http://127.0.0.1:8179/health
curl.exe --noproxy "*" -s -o NUL -w "%{http_code}" http://127.0.0.1:8178/
```

#### Запуск whisper.cpp против выдумок

На машине со службами `whisper-server` запускают с ключами против выдуманных титров: `-sns` не выдаёт неречевые токены, а `--vad` включает встроенный детектор речи. Файл модели детектора (`ggml-silero-*.bin`) скачивают со страницы выпусков `github.com/ggml-org/whisper.cpp` и кладут рядом с моделью распознавания. Пример строки запуска:

```powershell
whisper-server -m ggml-small.bin -l ru -t 4 -ac 768 --host 127.0.0.1 --port 8178 -sns --vad --vad-model ggml-silero-v5.1.2.bin
```

Ключи поддерживаются не всеми сборками: если программа их не понимает, запускайте как раньше. Ключ `-mc 0` не ставьте — он отключает подсказку с именем.

### Вариант Б: распознавание локально

1. Скачать сборку whisper.cpp для Windows со страницы выпусков `github.com/ggml-org/whisper.cpp` и модель `ggml-small.bin` (huggingface `ggerganov/whisper.cpp`).
2. Положить в каталог без кириллицы и пробелов, например `C:\tishka-tools\whisper`.
3. Экран «Голос» → «Служба распознавания»: выбрать «Запускать на этом компьютере», указать путь к `whisper-server.exe` и к модели, «Сохранить». Приложение запускает службу само.

На процессоре без видеокарты ответ занимает 2–3 секунды на фразу.

### Микрофон

Экран «Голос» → «Микрофон» → «Проверить микрофон»: фраза обычным голосом, на полоске видно, слышит ли её Тишка. Если Windows спросит доступ к микрофону — разрешить.

## Добавить ключ участника (на машине со службами)

PowerShell от имени администратора, одной строкой; вместо `КЛЮЧ` — открытый ключ участника целиком (начинается с `ssh-ed25519`):

```powershell
Add-Content C:\ProgramData\ssh\administrators_authorized_keys 'restrict,port-forwarding,permitopen="127.0.0.1:8178",permitopen="127.0.0.1:8179" КЛЮЧ' -Encoding ascii
```

Такой ключ может только пробрасывать два порта речи: без командной строки и без доступа к файлам. Убрать доступ — удалить строку из файла.

## Что проверить при функциональной проверке

1. Запуск без ключа: открывается основное окно на «Подключениях», ежа на экране нет. Задать ключ и перезапустить: открывается ёж со строкой ввода, основное окно не появляется. Повторный запуск приложения и значок возле часов открывают основное окно.
2. Текст: написать ёжику «который час» — ответ в облачке. Написать то же в чате основного окна: ответ виден в чате, ёж не появляется (а если был на экране — только думает и говорит, без облачка и карточки).
3. Голос: включить микрофон у ёжика, сказать фразу обычным голосом — распознано, ответ пришёл; сказать «Тишка, уходи» — ёжик спрятался, приложение осталось в значке.
4. Речь: ответ произносится, рот двигается; числа и время читаются словами.
5. Навыки: «покажи готовые навыки», «поставь итог недели», «оформи итог недели» → карточка ввода → результат в карточке → «Копировать» вставляется в письмо с оформлением.
6. Память: «запомни, что …» → запись на экране «Память»; в новом разговоре Тишка её использует.
7. Автоматизации: экран «Автоматизации» показывает навыки, «Запустить сейчас» работает.
8. Экран: «посмотри, что у меня на экране».
9. Интернет: «найди в Википедии, чем питается ёж».
10. Подключения (если настроены): «какие у меня сегодня встречи», «подготовь письмо …» → ссылка открывает черновик в браузере.

Находки записывать с шагами: что сказали или нажали, что ожидали, что получилось; полезны снимок окна и текст из консоли, где запущен `npm run dev`.
