# Приёмка правок: статус дефектов

Обновлено: 5 октября 2026, 08:30. Файл обновляется при каждом слиянии исправления в `main`.

Статусы:

- **исправлено** — правка в `main`, проверки пройдены (типы, тесты, сборка). Нужна повторная проверка руками.
- **в работе** — исправление пишется или проходит приёмку, в `main` его ещё нет.
- **в очереди** — задача поставлена, ещё не начата.

Как отмечать проверку и заводить новые дефекты — в следующем разделе.

## Порядок работы тестировщика

Файл правится прямо на рабочей машине, в Obsidian: каталог `C:\работа\tishka`, файл `docs/defects.md`. Локальный файл — источник истины; отправлять его никуда не нужно, отметки забираются отсюда. Статусы в файле обновляются при каждом слиянии исправления.

Перед проверкой перезапустить приложение, чтобы работал свежий код: закрыть Тишку («Выход» в значке возле часов), в каталоге проекта выполнить `npm run dev`.

### Отметки

Каждый дефект — строка списка с флажком. В Obsidian флажок ставится щелчком. Тестировщик меняет в файле только флажки:

- работает — поставить флажок;
- не работает или работает не так — флажок не ставить, описать словами тому, кто ведёт исправления.

Отмечать только строки со статусом «исправлено». Текст строк не менять.

### Новые дефекты и наблюдения

Всё найденное попадает в этот файл, в раздел «Очередь» в конце: либо тестировщик дописывает строку сам, либо сообщает словами, и строку вносит тот, кто ведёт исправления. Ничего не остаётся только в переписке.

Строка в очереди: `- **Н7** (новое; задача 88, в очереди). Что сделали, что ожидали, что получилось.` Номер — следующий по порядку.

Из очереди строки забираются в работу пачками: строка переезжает в список замечаний с номером Д, номером задачи и статусом «в работе», в очереди от неё остаётся пометка, куда она ушла. Пачка вливается целиком, после неё нужен один перезапуск приложения.
