# Тишка — правила для агента

Тишка — настольный помощник на Electron и TypeScript для Windows 11: персонаж поверх экрана, голос, агент на локальных моделях ДКС, инструменты через MCP, навыки-сценарии.

## Как работать

1. Задача приходит файлом из `tasks/`. Делай только то, что в ней написано, в перечисленных файлах.
2. Перед началом прочитай `docs/contracts.md`. Типы и интерфейсы оттуда менять нельзя. Если контракт мешает выполнить задачу, остановись и напиши, что именно мешает.
3. После изменений запусти `npm run typecheck` и `npm test`. Задача готова, когда обе команды проходят и выполнены пункты «Как проверить» из файла задачи.
4. В конце ответа перечисли: какие файлы изменены, что проверено, что осталось нерешённым.

## Стиль кода

- TypeScript в строгом режиме, без `any`. Модули ES.
- Ядро в `src/core/` не импортирует `electron`, кроме `src/core/secrets/`. Всё, что нужно от Electron, передаётся снаружи параметрами.
- Один модуль — одна ответственность. Функции короткие, имена на английском, комментарии только там, где неочевидно «почему».
- Асинхронный код на `async/await`. Ошибки внешних вызовов ловятся и превращаются в понятный результат, а не роняют приложение.
- Новые зависимости добавлять, только если они названы в задаче.
- Тесты на vitest в `tests/`, имя файла `<модуль>.test.ts`. Сеть и файловая система в тестах подменяются.
- Любая правка окна ежа, состояний, разговора, микрофона или речи заканчивается прогоном `npm run test:scenarios`. Новый дефект в этой области сначала добавляется сценарием в `tests/scenarios/`.

## Запреты

- Не читать и не выводить секреты. Не писать ключи, токены и пароли в код, тесты, журналы и файлы настроек. Ключ шлюза в тестах и скриптах берётся из переменной окружения `DKS_API_KEY`.
- Не выходить за пределы каталога `tishka/`.
- Не менять файлы в `tasks/` и `docs/`.
- Не выполнять `git push` и не устанавливать ничего глобально.
- Не завершать процессы, которые запущены не тобой. Запущенное для проверки приложение останавливать по его идентификатору процесса, а не по имени.

## Команды

| Команда | Что делает |
|---|---|
| `npm install` | Установка зависимостей |
| `npm run dev` | Запуск приложения в режиме разработки |
| `npm run typecheck` | Проверка типов |
| `npm test` | Тесты |
| `npm run test:scenarios` | Сценарные тесты ежа и голоса |
| `npm run build` | Сборка |
