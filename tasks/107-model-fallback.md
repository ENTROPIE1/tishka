# 107. Отказ одной модели шлюза: запасная модель и понятное сообщение

5 октября модель, выбранная в настройках (DKS-Apis), перестала отвечать: шлюз возвращал ошибку 500 «Cannot connect to host», остальные модели работали. Тишка сообщал «шлюз модели недоступен» и не работал, пока модель не сменили руками. Шлюз также отдаёт 502 на отдельных моделях.

## Что сделать

- Настройка `llm.fallbackModel` (строка, по умолчанию пусто) и то же для модели картинок `llm.visionFallbackModel`. Экран «Подключения» → «Модель»: поле «Запасная модель» под основной, с подсказкой «если основная не отвечает»; кнопка «Проверить» проверяет обе и показывает результат по каждой.
- Клиент шлюза (`src/core/llm/client.ts` и место вызова в агенте): при ошибке сервера (HTTP 5xx, отказ соединения, истечение времени ожидания первого ответа) запрос один раз повторяется на запасной модели, если она задана и отличается от основной. При ошибках 4xx (ключ, бюджет, неверный запрос) перехода нет. После перехода следующие запросы 5 минут идут сразу на запасную, затем снова пробуется основная. Отмена человеком (`AbortSignal`) повтором не считается.
- Человеку: при переходе — одна приглушённая строка в ленте «Модель <имя> не отвечает, работаю на <запасная>» (раз за период перехода, не вслух). Если запасной нет или она тоже отказала — сообщение называет модель и причину простыми словами и ведёт в настройки: «Модель DKS-Apis не отвечает (ошибка сервера). Смените модель в „Подключениях“» — вместо «шлюз недоступен». «Шлюз недоступен» остаётся только когда не отвечает сам адрес шлюза.
- Бюджет исчерпан (текст ошибки шлюза содержит `exceeded budget`) — отдельное сообщение: «На модель <имя> сегодня исчерпан лимит», с тем же предложением сменить модель. Идентификатор ключа и почта из текста ошибки шлюза в ленту, в историю и в журналы не попадают.
- Журнал времени: `model.fallback from=… to=… reason=…`.

## Как проверить

Тесты на подставном шлюзе: 500 и 502 основной — ответ с запасной и строка в ленте один раз; 401 и 429 — без перехода; обе отказали — сообщение с именем модели; пять минут запросы идут на запасную, потом возврат; отмена не вызывает перехода; исчерпанный бюджет — своё сообщение без идентификатора ключа; старые настройки без поля читаются. `npm run typecheck`, `npx vitest run --maxWorkers=1` (проверки по одной, память машины ограничена), `npm run build`. Обновить `docs/contracts.md`.

## Не делать

Не трогать окно ежа, голос, запись (`src/voice`, `src/renderer/pet`, `src/pet`).
