# 10. Наблюдения: следить за изменением

## Цель

Навык с триггером `watch` периодически вызывает инструмент и срабатывает, когда результат изменился. Пример: «следи за страницей» — раз в несколько минут читается номер версии страницы.

## Что сделать

`src/core/triggers/watcher.ts`

```ts
function createWatcher(deps: {
  skills: { list(): Promise<Skill[]> };
  registry: ToolRegistry;
  runner: { run(skill: Skill, inputs?: Record<string, unknown>): Promise<RunResult> };
  state: ReturnType<typeof createTriggerState>;   // из задачи 09, раздел watches
  events: EventBus;
  now: () => Date;
}): {
  start(): Promise<void>;     // проверка раз в 30 секунд
  stop(): void;
  tick(): Promise<void>;      // одна проверка; вызывается таймером и из тестов
  checkNow(skillId: string): Promise<{ changed: boolean; value?: string; error?: string }>;
};
```

1. Для каждого навыка с `trigger.type === 'watch'` проверка выполняется, если с прошлой прошло не меньше `everyMinutes` минут. Время прошлой проверки хранится в памяти, при первом `tick` после запуска проверяются все.
2. Проверка: вызвать `trigger.tool` с `trigger.args` через реестр. Значение для сравнения:
   - если задано `trigger.field` — поле из `data` по пути через точку (`version`, `items.0.id`), приведённое к строке;
   - иначе `content` целиком.
3. Первое полученное значение запоминается в `watches[skillId].last` без срабатывания.
4. Если значение отличается от `last`: запомнить новое, отправить `wake` с `source: 'trigger'`, запустить навык с входами `{ previous, current }`, после успешного запуска отправить `notify` с названием навыка и `skillId`.
5. Сбой инструмента (`ok: false`) или отсутствие поля: значение не меняется, счётчик `errors` растёт. На третьем сбое подряд отправляется одно событие `error` с названием навыка. Удачная проверка обнуляет счётчик.
6. Навык удалён — его запись в `watches` удаляется на следующей проверке.
7. Сбой одного наблюдения не мешает остальным.

Пресет `presets/watch-page.tishka.json` — «Следи за страницей»:

- вход `page_id` (обязательный);
- триггер `watch`: инструмент `confluence__get_page_version`, аргументы `{ "page_id": "{{inputs.page_id}}" }`, `everyMinutes: 2`, `field: "version"`;
- шаг `say`: «Страница обновилась».

Аргументы триггера проходят через `renderTemplate` из задачи 08 с входами навыка: значения берутся из `default` входов. Для пресета вход `page_id` получает `default` при сохранении навыка пользователем; в файле пресета `default` — пустая строка, и наблюдение с пустым `page_id` пропускается без ошибки.

## Как проверить

Тесты `tests/watcher.test.ts` с подменой реестра и времени:

- Первая проверка запоминает значение и не запускает навык.
- Значение не изменилось → навык не запускается.
- Значение изменилось → навык запущен один раз с `previous` и `current`, события `wake` и `notify` отправлены.
- `field: "version"` берёт поле из `data`; без `field` сравнивается `content`.
- Проверка не чаще `everyMinutes`: три `tick` за одну минуту дают один вызов инструмента.
- Три сбоя подряд → одно событие `error`; четвёртый сбой нового события не даёт; удачная проверка обнуляет счётчик.
- Состояние переживает перезапуск: новый наблюдатель на том же файле не срабатывает на прежнем значении.
- Пресет `watch-page` проходит `validateSkill`.
