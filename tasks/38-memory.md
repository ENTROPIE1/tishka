# 38. Долгая память с поиском и актуализацией

## Цель

Тишке можно сказать «запомни» — и он запомнит факты надолго: адреса почты коллег, ссылки, договорённости, предпочтения. Позже он сам находит нужные записи по смыслу фразы и использует их, а устаревающие записи время от времени предлагает проверить.

Пример: «Тишка, запомни почты команды» → карточка ввода (задача 37) → человек вставляет список → Тишка раскладывает его на отдельные записи. Через неделю: «Подготовь письмо Ане из тестирования» → адрес берётся из памяти.

## Что сделать

### Хранилище

`src/core/memory/store.ts` — без `electron`, файл `memory.json` в каталоге данных приложения, запись через общую очередь (как состояние расписания), атомарно.

```ts
interface MemoryRecord {
  id: string;
  text: string;            // один факт одной фразой: «Аня Петрова, тестирование — anna@example.ru»
  tags: string[];          // короткие метки: «почта», «команда»
  created: string;         // ISO
  updated: string;
  reviewAt?: string;       // когда предложить проверить; нет — не устаревает
  source: 'user' | 'skill';
}

function createMemoryStore(opts: { filePath: string; now: () => Date }): {
  add(input: { text: string; tags?: string[]; reviewDays?: number; source?: 'user' | 'skill' }): Promise<MemoryRecord>;
  update(id: string, patch: { text?: string; tags?: string[]; reviewDays?: number | null }): Promise<MemoryRecord | undefined>;
  remove(id: string): Promise<boolean>;
  list(): MemoryRecord[];
  search(query: string, limit?: number): MemoryRecord[];
  due(): MemoryRecord[];                       // записи, у которых reviewAt уже наступил
  confirm(id: string): Promise<MemoryRecord | undefined>;   // «всё ещё верно»: reviewAt сдвигается на тот же срок
};
```

- Предел: 2000 записей, текст записи до 500 символов; сверх предела — понятная ошибка.
- `add` с текстом, почти совпадающим с существующей записью (после приведения к нижнему регистру и удаления знаков препинания), не создаёт дубль, а обновляет `updated` существующей.

### Поиск

`src/core/memory/search.ts` — чистая функция, без сети:

- текст и запрос приводятся к нижнему регистру, «ё» → «е», разбиваются на слова; слова короче трёх букв и служебные («для», «или», «это»…) отбрасываются;
- русские слова сравниваются по началу: совпадением считается общий префикс не короче 4 букв или 70 % длины более короткого слова (чтобы «Ане» находило «Аня», «тестирования» — «тестирование»);
- оценка записи — число совпавших слов запроса, совпадение с меткой весит вдвое; при равенстве выше более свежая запись;
- записи с нулевой оценкой не возвращаются.

Поиск спрятан за интерфейсом `search(query, limit)`, чтобы позже заменить его поиском по векторам, не трогая остальной код.

### Инструменты агента

`src/core/memory/tools.ts`, источник `builtin`:

- `memory_save { items: { text, tags?, reviewDays? }[] }` — сохраняет несколько записей за один вызов; возвращает, сколько добавлено и сколько обновлено;
- `memory_search { query, limit? }`;
- `memory_update { id, text?, tags?, reviewDays? }`;
- `memory_forget { id }`;
- `memory_confirm { ids: string[] }`.

### Память в диалоге

- Перед каждым обращением к модели ядро ищет записи по фразе человека (до 8 штук) и добавляет их в системное сообщение блоком «Что ты помнишь по теме» — по строке на запись, с `id`. Блок не добавляется, если ничего не нашлось.
- В системное сообщение — правила: сохранять только по прямой просьбе человека («запомни», «запиши себе») или после вопроса «Запомнить?» и согласия; большой список разбивать на отдельные записи, по одному факту в записи; для адресов, должностей, ссылок и сроков ставить `reviewDays` 90, для предпочтений человека — не ставить; пароли, токены и ключи не запоминать никогда и сказать об этом; если человек просит запомнить много, а текста нет — попросить его через `ask`; найденные записи использовать молча, не пересказывая список памяти вслух.
- Ответ после сохранения: вслух одно предложение, в карточке — список сохранённого.

### Актуализация

- Раз в сутки (и при запуске приложения, если с прошлой проверки прошли сутки) планировщик смотрит `due()`. Если есть записи к проверке — событие `notify` с репликой «Проверим, что я помню?» и карточкой-списком этих записей (не больше 10 за раз).
- Человек отвечает обычной фразой: «всё верно» → `memory_confirm`; «у Ани теперь другой адрес …» → `memory_update`; «забудь про …» → `memory_forget`.
- Напоминание о проверке не чаще одного раза в сутки; без ответа записи остаются и предлагаются на следующий день.

### Окно

В окне настроек раздел «Память»: список записей (текст, метки, дата проверки), поле поиска, кнопки «Изменить», «Забыть» у записи и «Забыть всё» с подтверждением. Стили только в файлах css.

## Как проверить

Тесты:

- `add`, `update`, `remove`, `list` переживают пересоздание хранилища с тем же файлом.
- Почти одинаковый текст не создаёт дубль.
- Поиск: запись «Аня Петрова, тестирование — anna@example.ru» находится по запросам «письмо Ане из тестирования» и «почта Петровой», не находится по «расписание встреч»; совпадение с меткой поднимает запись выше.
- `due` и `confirm` с подменой времени: запись с `reviewDays: 90` попадает в `due` через 91 день, после `confirm` — нет.
- `memory_save` с тремя записями добавляет три записи; текст длиннее предела — ошибка для этой записи, остальные сохраняются.
- В системном сообщении при найденных записях есть блок «Что ты помнишь по теме», при пустой памяти блока нет.
- Проверка актуальности: одна реплика `notify` в сутки, в карточке не больше 10 записей.
- `npm run typecheck`, `npm test`, `npm run build`.

Скрипт `scripts/check-memory.ts` на живом шлюзе: «Запомни: Аня Петрова из тестирования, anna@example.ru; Борис Ильин, аналитика, boris@example.ru» → в памяти две записи; новая беседа, «Кому писать по тестированию?» → в ответе адрес Ани; «Запомни пароль qwerty» → запись не создана.

## Не делать

Векторный поиск и обращения к сети для поиска, синхронизация памяти между компьютерами, автоматическое запоминание без просьбы человека.
