# 72. Путь к настройкам от ежа

Когда ключ шлюза задан, приложение запускается сразу с ежом, основное окно не открывается. Видимого пути к настройкам у ежа нет: только меню значка в области уведомлений по правой кнопке и повторный запуск. Пользователь, не знающий про значок, до настроек не добирается.

## Что сделать

- В строке ввода ежа (`src/renderer/pet/composer.ts`, `composer.css`) добавить небольшую кнопку со значком шестерёнки, подсказка и `aria-label` — «Настройки». Нажатие открывает основное окно на экране «Подключения» через уже существующий вызов `openSettings` из preload. Кнопка оформлена так же, как кнопка микрофона в этой строке (те же размеры и классы), строку не расширяет за пределы окна ежа.
- Кнопка работает в любом состоянии ежа, в котором видна строка ввода, в том числе пока ёж думает или говорит. Ёж при этом не прячется.
- Значок в области уведомлений (`src/main/pet-tray.ts`): левый щелчок открывает основное окно на экране чата (`deps.openChat()`). Меню по правой кнопке не меняется.
- В `README.md`, раздел «Первая настройка», одной фразой дополнить, как открыть основное окно: кнопка «Настройки» у строки ввода ежа, щелчок по значку.

## Как проверить

Тесты: в разметке строки ввода есть кнопка «Настройки», нажатие вызывает `openSettings` один раз; обработчик левого щелчка значка вызывает `openChat`. Существующие тесты строки ввода (фокус, ввод, микрофон) проходят без изменений. `npm run typecheck`, `npx vitest run --maxWorkers=2`, `npm run build`.

## Не делать

Не менять логику появления и ухода ежа, фокус строки ввода, перетаскивание. Не трогать `src/core`. Не добавлять новых каналов связи между окнами, если хватает существующего `openSettings`. Файлы не длиннее 200 строк.
