# 52. Служба синтеза поверх лаборатории голосов

## Цель

Есть готовый каталог «лаборатория голосов» (лежит вне репозитория, на машине со службами речи): окружение Python 3.11, модели Silero и файл `voice_window.py`. Сейчас это настольное окно. Нужна служба HTTP с интерфейсом, под который написан Тишка (`docs/contracts.md`, синтез): `GET /health`, `POST /tts`.

Это исключение из правила «только TypeScript»: служба пишется на Python, один файл, только стандартная библиотека.

## Что известно о лаборатории

В `voice_window.py` есть (менять его нельзя, только импортировать):

```python
class Synthesizer:
    def render(self, text, voice, speed=1.0, pitch=0.0) -> bytes  # готовый WAV целиком, моно, 16 бит
```

- `voice` — код голоса: `ru_roman`, `ru_alexandr`, `ru_ekaterina` (Silero).
- `speed` от 0.6 до 1.6, `pitch` в полутонах от -6 до 12; вне диапазона — `ValueError`.
- Первый вызов загружает модели (десятки секунд), следующие быстрые. Объект не потокобезопасен.
- Текст без русских букв или длиннее примерно 800 знаков модель может не принять (исключение).
- Модуль при импорте подключает `tkinter` и `winsound` — это нормально, окно не создаётся.

## Что сделать

Файл `services/voice-lab/tts_server.py`:

- Запуск: `python tts_server.py --lab <каталог лаборатории> [--host 127.0.0.1] [--port 8179] [--voice ru_roman] [--speed 1.10] [--pitch 4.5]`. Значения по умолчанию — как в примере. Слушать только указанный адрес.
- Каталог `--lab` добавляется в `sys.path`, оттуда импортируется `Synthesizer`. Нет каталога или файла — понятное сообщение и код выхода 2.
- После старта в фоне прогревается голос (синтез короткой фразы «Привет.»). `GET /health`: пока идёт прогрев — код 503 и `{"status":"loading"}`; после — 200 и `{"status":"ok","engine":"Silero","voice":"<код голоса>","speed":1.1,"pitch":4.5}`; если прогрев упал — 500 и `{"status":"error","error":"…"}`.
- `POST /tts`, тело JSON `{"text":"…"}`; необязательные поля `voice`, `speed`, `pitch` перекрывают значения запуска. Ответ — `audio/wav`.
  - Пустой текст, не JSON, тело больше 20 000 байт — 400 и `{"error":"…"}`.
  - Длинный текст режется на куски до 500 знаков по концам предложений (`.`, `!`, `?`, `…`, перевод строки), если предложение длиннее — по запятым и пробелам. Куски синтезируются по очереди и склеиваются в один WAV (параметры берутся из первого куска, между кусками пауза 150 мс тишины).
  - Кусок без единой русской буквы пропускается; если пропущены все — 422 и `{"error":"…"}`.
  - Ошибка синтеза — 500 и `{"error":"…"}`, служба продолжает работать.
- Синтез под одной блокировкой: одновременные запросы идут по очереди.
- В консоль — одна строка на запрос: время, число знаков, длительность синтеза в мс. Сам текст не печатать.
- Логика (разбор аргументов, резка текста, склейка WAV, обработчик запросов) отделена от загрузки лаборатории так, чтобы в тестах подставить поддельный синтезатор.

Файл `services/voice-lab/test_tts_server.py` (`unittest`, без настоящей лаборатории, поддельный синтезатор возвращает короткий WAV из `wave`): здоровье до и после прогрева, обычный запрос, пустой текст, не JSON, текст без русских букв, длинный текст (несколько кусков, один корректный WAV, длительность равна сумме кусков и пауз), ошибка синтеза не роняет службу, перекрытие `voice/speed/pitch` в запросе. Служба в тестах поднимается на порту 0 (свободный).

Файл `services/voice-lab/README.md`: что это, как запустить, пример проверки через `curl.exe`, два рекомендованных набора: Роман `ru_roman` 1.10 / 4.5; Екатерина `ru_ekaterina` 1.05 / 2.5.

## Как проверить

- `python -m unittest discover -s services/voice-lab -v` — все проходят (на машине Python 3.12, этого достаточно).
- `npm run typecheck`, `npx vitest run --maxWorkers=2` — как были.
