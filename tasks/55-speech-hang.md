# 55. Речь замолкает навсегда, если её перебить в момент начала

Находка 1 из `tasks/reports/54-windows.md` (там же тест, который показывает ошибку).

## Что сделать

- `src/renderer/pet/speaker.ts`: `stop()` во время декодирования (до начала воспроизведения) должен приводить ровно к одному вызову `onDone`. Каждый `play` заканчивается ровно одним `onDone`: по окончании звука, по `stop`, по ошибке декодирования, при вытеснении следующим `play`.
- `src/main/index.ts` (место, где создаётся `createSpeechOutput`, функция `play`): обещание завершается не только по сообщению `speak-done`, но и по `abort` сигнала, и по страховочному сроку (длительность звука неизвестна — срок 60 секунд). Позднее `speak-done` от прежнего звука не должно завершать следующий: сопоставлять по номеру воспроизведения. Логику вынести в отдельный модуль `src/main/pet-speak-play.ts` с тестами, в `index.ts` оставить только подключение.
- `src/main/pet-window.ts`, `reload()`: если окно перезагружается во время речи, ожидающее обещание завершается.
- Наблюдение за памятью (`index.ts`, флаг `processing`): пока идёт речь (`speak.start` … `speak.end`), приложение считается занятым.

## Как проверить

Тесты: тест из отчёта (перенести в `tests/`), `stop` после начала, два `play` подряд, ошибка декодирования; для модуля главного процесса — завершение по `speak-done`, по `abort`, по сроку, позднее сообщение от прежнего звука, перезагрузка окна. После остановленной реплики следующая реплика озвучивается.

`npm run typecheck`, `npx vitest run --maxWorkers=2`, `npm run build`.

## Не делать

Не трогать `src/renderer/shared`, `src/renderer/chat`, `src/renderer/pet/pet-card.ts`. Файлы не длиннее 200 строк (кроме уже длинного `index.ts` — его не увеличивать больше чем на 10 строк). Стили только в css.
