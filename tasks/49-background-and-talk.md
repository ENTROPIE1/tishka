# 49. Всегда в фоне, разговор по умолчанию, ссылки в карточке, «уходи»

## Цель

Четыре замечания после просмотра вторым человеком.

## 1. Ссылка в карточке ломает окно (критично)

Щелчок по ссылке в карточке окна-питомца (например «Открыть черновик» письма) загружает страницу прямо в окно-питомец: приложение теряет свой интерфейс. В окне чата щелчки по ссылкам перехватываются, в окне-питомце — нет.

- Общий перехват в одном месте — `src/renderer/shared/links.ts`: щелчок по любому элементу `a` с адресом `http:` или `https:` внутри окна отменяет переход и открывает адрес во внешнем браузере через `window.tishka.openExternal`. Подключить в окне-питомце, окне чата (вместо нынешнего своего обработчика) и на стенде.
- Страховка в главном процессе для всех окон приложения (чат, питомец, стенд), одной функцией `guardNavigation(window)`: `will-navigate` на адрес, отличный от собственной страницы окна, отменяется, а адрес `http/https` открывается во внешнем браузере; `setWindowOpenHandler` — то же и `action: 'deny'`. Скрытое окно чтения страниц (`web-window.ts`) под это правило не попадает.
- Длинные ссылки на черновики (тема и текст письма в адресе) должны доходить до браузера целиком: проверить, что `openExternal` не обрезает и не перекодирует адрес; если адрес длиннее 2000 символов, инструмент черновика сокращает текст письма в ссылке до предела и добавляет в карточку полный текст с кнопкой «Копировать» и подсказкой «Текст длинный — вставьте его в письмо из буфера».
- Пройти путь команды «подготовь письмо» целиком тестом: навык или инструмент черновика → карточка со ссылкой → щелчок → вызов `openExternal` с тем же адресом; окно-питомец при этом остаётся на своей странице.

## 2. Всегда в фоне, без холодного старта

Сейчас при каждом обращении заметна задержка: микрофон открывается заново, службы «просыпаются». Тишка должен быть готов сразу.

- Приложение живёт в области уведомлений постоянно; окно-питомец создаётся один раз при запуске и только прячется и показывается (проверить, что нигде не пересоздаётся и страница не перезагружается при появлении).
- **Тёплое состояние.** Пока приложение работает: служба распознавания запущена; при включённом отклике на имя или в течение `Config.app.warmMinutes` (по умолчанию 30) после последнего обращения микрофон остаётся открытым (поток не закрывается между фразами и между появлениями), оценка шума сохраняется; заготовленные фразы синтеза лежат в памяти. Появление по клавише или имени — без ожидания: запись начинается с уже открытого потока.
- **Долгий простой.** Если отклик на имя выключен и обращений не было дольше `warmMinutes`, микрофон закрывается; первое обращение после этого открывает его заново (это и есть допустимый холодный старт).
- **Предел памяти.** Раз в минуту главный процесс считает память приложения (`app.getAppMetrics()`, сумма по процессам) и память службы распознавания. Предел — `Config.app.memoryLimitMb` (по умолчанию 1500, без службы распознавания). При превышении в простое (нет разговора, нет выполняющейся просьбы): сначала перезагружается окно-питомец и окно чата (история и настройки на диске, состояние восстанавливается), запись в журнал; если через минуту предел всё ещё превышен — одно уведомление текстом «Занимаю много памяти, перезапущусь» и мягкий перезапуск приложения (`app.relaunch()` и выход) не чаще одного раза в час. Во время разговора ничего не перезапускается.
- **Автозапуск.** Настройка `Config.app.autostart` (по умолчанию `false`): запуск вместе с Windows свёрнутым в область уведомлений (`app.setLoginItemSettings`, аргумент `--hidden`: основное окно не открывается, ёжик появляется по клавише или имени). Переключатель «Запускать вместе с Windows» на экране «Характер» или в новом небольшом разделе «Приложение» там же, где остальные общие настройки; там же — число «Держать микрофон наготове, минут» и «Предел памяти, МБ».
- Поля `Config.app` добавить в `docs/contracts.md`, типы, значения по умолчанию, разбор.

## 3. Разговор включён по умолчанию

Сейчас после обращения по имени микрофон приходится нажимать перед каждой фразой.

- Настройка `Config.voice.talkByDefault: boolean` (по умолчанию `true`), переключатель «Слушать сразу, как Тишка появился» в группе «Как звать Тишку».
- При `true` режим разговора включается при любом появлении Тишки по обращению человека: по имени (в том числе когда сказано одно имя, без просьбы), по горячей клавише, по щелчку на ёжике или пункту «Позвать Тишку». Дальше — как сейчас: фраза → ответ → снова слушает, пока не уйдёт по тишине, по просьбе или пока человек не выключит микрофон.
- Человек выключил микрофон значком — до конца этого появления Тишка не слушает; при следующем появлении снова слушает (настройка не меняется). Чтобы выключить насовсем — переключатель в настройках.
- При появлении по уведомлению (наблюдение, напоминание) режим разговора не включается.
- Если служба распознавания не готова — режим не включается, строка ввода работает, ошибки в облачке нет.

## 4. «Тишка, уходи»

- По просьбе уйти (и по тишине) ёжик прячется с экрана с анимацией ухода, строка ввода и карточки закрываются; приложение при этом продолжает работать в области уведомлений: расписание, наблюдения и отклик на имя работают. Процесс не завершается.
- Прячется и при включённом «Режиме питомца» (в этом режиме он обычно остаётся на экране): просьба уйти сильнее режима; вернуть — именем, клавишей или значком.
- После ухода отклик на имя снова активен не позже чем через секунду.
- Проверить, что ни «уходи», ни закрытие окон не вызывают `app.quit()`; выход — только пункт «Выход» в значке.

## 5. Подпись состояния

Подпись состояния под ёжиком («ждёт», «слушает», «думает») остаётся видимой — если её нет в текущей разметке окна-питомца, вернуть.

## Как проверить

Тесты:

- щелчок по ссылке в карточке окна-питомца вызывает `openExternal` и не меняет адрес окна; `guardNavigation` отменяет переход на внешний адрес и разрешает собственную страницу;
- адрес черновика длиной 3000 символов сокращён до предела, полный текст — в карточке;
- тёплое состояние: два появления подряд — микрофон открыт один раз (подменный микрофон считает открытия); простой дольше `warmMinutes` при выключенном отклике на имя закрывает микрофон;
- предел памяти (подменные метрики и время): превышение в простое → перезагрузка окон, повторное превышение → перезапуск не чаще раза в час; во время разговора — ничего;
- `talkByDefault`: появление по имени без просьбы, по клавише и по щелчку включает режим разговора; по уведомлению — нет; выключение значком действует до конца появления;
- «уходи»: окно спрятано, `app.quit` не вызван, отклик на имя активен; то же при включённом режиме питомца;
- подпись состояния присутствует в разметке и видима.

`npm run typecheck`, `npx vitest run --maxWorkers=2`, `npm run build`.

## Не делать

Изменение раскладки окна-питомца (её меняет другая задача), калибровка микрофона, выбор движка речи.
