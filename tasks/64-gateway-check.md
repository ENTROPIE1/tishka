# 64. Другой шлюз моделей: проверка подключения и список моделей

## Цель

Участник может работать через другой адрес шлюза (совместимый с OpenAI: `/chat/completions`, `/models`). Поля «Адрес шлюза», «Модель», «Модель для картинок» и «Ключ шлюза» в разделе «Модель» уже есть и применяются без перезапуска. Не хватает проверки: человек не знает, верен ли адрес, принят ли ключ и как называются модели на этом шлюзе.

## Что сделать

- Ядро (`src/core/llm`): функция проверки шлюза по адресу, ключу и имени модели, без сохранения настроек.
  1. `GET <адрес>/models` с ключом — список имён моделей (поле `data[].id`). Если шлюз не отдаёт список (404 и подобное) — это не ошибка, список пуст.
  2. `POST <адрес>/chat/completions` с указанной моделью, одним коротким сообщением и `max_tokens: 1`.
  Результат: `{ ok, models: string[], error?: string, ms }`. Сообщения об ошибках по-русски и различимы: адрес недоступен, ключ не принят (401/403), модели с таким именем нет (404 или ошибка шлюза о модели), шлюз ответил ошибкой N, не ответил за 20 секунд. Ключ в сообщения и журнал не попадает.
- Главный процесс и `preload`: канал `settings`-уровня для этой проверки. Ключ берётся из поля, если оно заполнено, иначе — сохранённый. В окно ключ не возвращается.
- Раздел «Модель» (`src/renderer/settings/model-section.ts`): кнопка «Проверить» рядом с «Сохранить». Проверяет значения из полей (ещё не сохранённые). Показывает «Шлюз отвечает, модель <имя>, N мс» или ошибку. Если список моделей получен — под полями «Модель» и «Модель для картинок» подсказка-список (`datalist`), чтобы имя можно было выбрать; имена, которых нет в списке, помечаются предупреждением «такой модели в списке шлюза нет».
- Адрес нормализуется при сохранении и проверке: пробелы по краям и завершающие `/` убираются; адрес без `http://` или `https://` — ошибка с подсказкой. Если адрес оканчивается на `/chat/completions`, этот хвост убирается.
- `README.md`, раздел «Первая настройка»: два предложения о другом шлюзе — где менять адрес и имена моделей, кнопка «Проверить».
- `docs/contracts.md`: описать новый канал.

## Как проверить

Тесты (поддельный `fetch`): успешная проверка со списком; шлюз без `/models`; 401; неизвестная модель; недоступный адрес; срок ожидания; нормализация адреса (хвостовые косые, `/chat/completions`, без схемы); ключ не встречается в тексте ошибки. Тест раздела настроек: кнопка показывает результат, список моделей появляется.

`npm run typecheck`, `npx vitest run --maxWorkers=2`, `npm run build`.

## Не делать

Не менять значения по умолчанию в `src/core/config.ts`. Не трогать `src/voice`, `src/renderer/pet`, `src/renderer/chat`. Файлы не длиннее 200 строк. Стили только в css.
