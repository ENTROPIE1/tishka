# 74. После просьбы уйти ёж остаётся на экране с мёртвой строкой ввода

Шаги: ёж на экране, сказать или написать ему «Всё хорошо, можешь пока быть свободен». Тишка отвечает «Хорошо, буду рядом. Позовёшь — прибегу.» Ожидание: ёж договаривает ответ и уходит. Получилось: ёж остался на экране, но строка ввода не принимает щелчки.

## Вероятная причина (проверить, не принимать на веру)

Уход (`leave` в `src/main/pet-lifecycle.ts`) начинается раньше или одновременно с ответной репликой. События ответа (`speak.start`, `reply` и другие в `src/pet/state.ts`) переводят ежа из `leave` обратно в видимое состояние, минуя `appear`: окно при этом видно, поэтому `showAtRest` и `activation.sendPointer()` не вызываются, а окно ежа считает себя скрытым и держит окно прозрачным для мыши (`src/renderer/pet/interactivity.ts`, `setIgnoreMouseEvents`).

## Что сделать

- Найти действительную причину по коду и тестом воспроизвести последовательность: просьба уйти → уход → события ответа той же реплики.
- Правило: если на реплику, вызвавшую уход, есть ответ, ёж сначала показывает и договаривает ответ, затем уходит одной анимацией ухода и скрывается. Уход не отменяется событиями этой же реплики. Новый вызов (имя, клавиша, щелчок по значку, сообщение из строки ежа) после ухода работает как обычно.
- Инвариант: пока ёж виден на экране в любом состоянии, кроме анимации ухода, строка ввода принимает щелчки и ввод. Любой переход из `leave` или `hidden` в видимое состояние пересчитывает интерактивность так же, как появление.
- Во время анимации ухода строка ввода скрыта или неактивна вместе с ежом, а не висит на экране отдельно.

## Как проверить

Тесты модели состояния: `leave` + события ответа → ответ показан, затем `leave` → `hidden`; после `hidden` событие вызова даёт `appear`. Тест окна: переход в видимое состояние из `leave` вызывает пересчёт интерактивности. Существующие тесты задач 68, 69, 70 проходят без ослабления. `npm run typecheck`, `npx vitest run --maxWorkers=2`, `npm run build`.
