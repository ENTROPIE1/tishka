# 112. Подтверждение человеком для инструментов, которые что-то меняют

Правило продукта: Тишка сам только читает и готовит, отправляет человек. Свои инструменты ядра (календарь, память, навыки) и серверы MCP, подключённые пользователем, могут менять данные (`readOnly: false`). Для чужих серверов это должно проходить через подтверждение человеком.

## Что сделать

- Настройка подключения `confirmChanges` (по умолчанию `true` для серверов MCP, добавленных пользователем; для встроенных инструментов ядра — календарь, память, навыки, режим речи — подтверждение не нужно, они и так безопасны и обратимы). В карточке подключения на экране «Подключения» переключатель «Спрашивать перед изменениями».
- Реестр инструментов (`src/core/tools/registry.ts`): вызов инструмента с `readOnly: false` от подключения с `confirmChanges` не выполняется сразу, а ставит вопрос: событие `confirm.request` с идентификатором, именем подключения, названием инструмента и коротким описанием действия с аргументами (без секретов, не длиннее 300 знаков). Ответ человека — `confirm(id, yes|no)` через канал окна. «Да» — инструмент выполняется, «Нет» — инструмент возвращает ошибку «Человек не подтвердил», модель получает её как результат и говорит об этом одной фразой. Ожидание не дольше 2 минут, затем считается отказом. Пока ждёт — ход не завершается, но «стоп» и новая реплика снимают вопрос как отказ.
- Окно ежа: в облачке «Выполнить <действие> через <подключение>?» и две кнопки «Да» и «Нет» (как кнопки карточки, стиль существующих). Голосом: «да», «давай», «подтверждаю» — да; «нет», «отмена», «не надо» — нет (только пока вопрос открыт; модуль разбора ответа отдельный, с тестами). Окно чата: та же строка с кнопками в ленте.
- Навыки по расписанию и слежение (фон, человека нет): меняющие инструменты с подтверждением не выполняются, а шаг завершается ошибкой «Нужно подтверждение, выполните навык вручную», в уведомлении — об этом.
- В подсказку модели — одна строка: некоторые действия требуют подтверждения человека; если отказ — не повторять попытку.
- `docs/contracts.md`: раздел «Подтверждение изменений».

## Как проверить

Тесты: инструмент с подтверждением ждёт ответа; «да» выполняет; «нет» и истечение времени возвращают ошибку; «стоп» снимает вопрос; `readOnly: true` и встроенные инструменты не спрашивают; выключенный `confirmChanges` не спрашивает; фоновый запуск не спрашивает и завершается ошибкой; разбор голосового ответа; облачко ежа с кнопками (jsdom); старые настройки без поля читаются как `true`. Сценарий в `tests/scenarios`: реплика → вызов меняющего инструмента → вопрос в облачке → «да» голосом → выполнение. `npm run typecheck`, `npm run test:scenarios`, `npx vitest run --maxWorkers=1` (по одной, память ограничена), `npm run build`.

## Не делать

Не трогать запись и распознавание (`src/voice`, кроме отдельного модуля разбора ответа). Не менять серверы MCP. Файлы не длиннее 200 строк.
