# 15. Окно чата

## Цель

Окно, в котором видна вся переписка с Тишкой: реплики пользователя, ответы, карточки с содержанием. Голосовой диалог попадает в ту же историю. Отсюда же можно писать Тишке текстом.

## Что сделать

### История

`src/core/history.ts` — без `electron`:

```ts
interface HistoryEntry {
  id: string;
  at: string;                       // ISO
  from: 'user' | 'tishka' | 'system';
  text: string;                     // реплика пользователя, say Тишки или текст уведомления
  panel?: Panel;
  mood?: Mood;
}

function createHistory(filePath: string, events: EventBus, now: () => Date): {
  start(): Promise<void>;           // читает файл, подписывается на события
  stop(): void;
  list(limit?: number): HistoryEntry[];   // последние записи по порядку, по умолчанию 200
  clear(): Promise<void>;
};
```

- Файл `history.jsonl` в каталоге данных: одна запись — одна строка JSON. Повреждённые строки пропускаются.
- Из событий в историю попадают: `listen.end` — запись `user`; `reply` — запись `tishka` с `say`, `show` и `mood`; `notify` — запись `system` с заголовком; `error` — запись `system` с текстом ошибки.
- Записи дописываются в конец файла. Если строк больше 2000, при запуске файл сокращается до последних 1000.
- Секретов в истории нет: история пишет только то, что пришло в событиях.

Ядро (`src/core/app.ts`): создаёт историю в `dataDir/history.jsonl`, запускает в `start()`, останавливает в `stop()`, отдаёт наружу методами `history(limit?)` и `clearHistory()`.

### Окно

Каталог `src/renderer/chat/`: `index.html`, `chat.ts`, `chat.css`, `markdown.ts`. Без сторонних библиотек и без фреймворков. Сборка: вторая точка входа в `electron.vite.config.ts`; прежняя заглушка `src/renderer/index.html` удаляется, главный процесс открывает окно чата.

Мост (`src/main/preload.ts`, `src/main/ipc.ts`) дополнить:

| Метод в `window.tishka` | Что делает |
|---|---|
| `history(limit?)` | Возвращает записи истории |
| `clearHistory()` | Очищает историю |
| `openExternal(url)` | Открывает ссылку в браузере; главный процесс пропускает только `http` и `https` |
| `copyText(text)` | Кладёт текст в буфер обмена через главный процесс |

Что видно в окне:

- Лента сообщений: реплики пользователя справа, Тишки слева, системные записи по центру мелким шрифтом. У каждой записи время.
- Под репликой Тишки — карточка, если есть `panel`:
  - `text`: заголовок и текст с простой разметкой;
  - `list`: заголовок и пункты; пункт со ссылкой открывается через `openExternal`;
  - `image`: заголовок и картинка по пути `path`.
- У каждой карточки кнопка «Копировать»: для `text` копируется исходный текст разметки, для `list` — пункты построчно с подзаголовками и ссылками. После нажатия на секунду показывается «Скопировано».
- Пока Тишка думает (между `think.start` и `reply` или `error`), внизу ленты строка «Тишка думает…»; при `tool.start` — «Тишка использует инструмент» с названием.
- Поле ввода внизу: Enter отправляет, Shift+Enter — новая строка. Пустой текст не отправляется. После отправки поле очищается.
- При открытии показываются последние 200 записей, лента прокручена вниз. Новая запись прокручивает ленту вниз, если пользователь не листал вверх.
- Кнопка «Очистить историю» с подтверждением.

`src/renderer/chat/markdown.ts`:

```ts
function renderMarkdown(source: string): string;   // возвращает безопасный HTML
```

- Сначала весь текст экранируется (`&`, `<`, `>`, кавычки), затем применяется разметка: абзацы, списки `- ` и `1. `, заголовки `#`–`###`, `**жирный**`, `` `код` ``, блоки кода в тройных кавычках, ссылки `[текст](https://...)`.
- Ссылка создаётся только для `http` и `https`; иначе остаётся текстом. Ссылки открываются через `openExternal`, а не переходом внутри окна.
- Теги из исходного текста никогда не попадают в HTML.

Требования к окну: `contextIsolation: true`, `nodeIntegration: false`, в `index.html` — политика `Content-Security-Policy` без `unsafe-inline` для скриптов. Вид спокойный, читаемый, светлая и тёмная тема по настройке системы.

## Как проверить

Тесты `tests/history.test.ts`, `tests/markdown.test.ts`:

- События `listen.end`, `reply` с панелью, `notify`, `error` дают записи в правильном порядке и с правильными полями.
- История переживает перезапуск: новый экземпляр на том же файле видит записи.
- Повреждённая строка в файле пропускается.
- Файл из 2100 строк при запуске сокращается до 1000 последних.
- `clear()` очищает список и файл.
- `renderMarkdown`: абзацы, оба вида списков, жирный, код, блок кода, ссылка `https`.
- `<script>alert(1)</script>` в исходном тексте попадает в результат экранированным.
- Ссылка `javascript:alert(1)` не превращается в ссылку.

Тест `tests/app.test.ts` дополнить: после `handleUserText` в `history()` есть запись пользователя и запись Тишки.

Проверка вручную: `npm run dev` открывает окно чата; сообщение «утро пятницы» даёт ответ Тишки в ленте; после перезапуска история на месте.

## Не делать

Окно-питомец, экран настроек, голос, отправку файлов и картинок.
