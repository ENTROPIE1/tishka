# 86. Сказанное при выключенном микрофоне приходит разом после включения

Шаги: микрофон у ежа выключен (разговор выключен). Человек говорит несколько фраз — ёж не реагирует. Человек включает микрофон — Тишка получает сказанное раньше, как будто это реплики разговора.

## Причина

При выключенном разговоре прослушивание имени продолжает записывать фразы и отправлять их на распознавание (`src/voice/wake-flow.ts`, `handlePhrase`). Распознавание идёт по очереди и занимает секунды. Решение, считать ли текст репликой разговора, принимается в `routeText` по состоянию `conversation` на момент, когда вернулся текст, а не на момент, когда фраза была сказана. Фразы, сказанные при выключенном разговоре и ещё не распознанные (идущий запрос и ждущая `pending`), после включения уходят в ядро как реплики.

## Что сделать

- Каждая фраза запоминает, каким был разговор в момент её начала (или номер «эпохи» разговора, который меняется при каждом включении и выключении). Распознанный текст направляется по состоянию на момент фразы: сказанное при выключенном разговоре проверяется только на имя и никогда не становится репликой разговора.
- Включение разговора (щелчком, клавишей, по имени, при появлении) отбрасывает ждущую фразу и помечает идущее распознавание устаревшим: его результат проверяется только на имя.
- Симметрично: фраза, сказанная при включённом разговоре, но распознанная после его выключения или ухода ежа, в ядро не уходит.
- Сценарий в `tests/scenarios`: разговор выключен, две фразы сказаны, включение разговора, распознавание возвращает тексты — ядро не получило ни одной; следующая фраза после включения — получена.

## Как проверить

Тесты `wake-flow` на оба направления и на ждущую фразу; сценарий. `npm run typecheck`, `npm run test:scenarios`, `npx vitest run --maxWorkers=1`, `npm run build`.

## Не делать

Не выключать прослушивание имени при выключенном разговоре. Не менять паузу записи и детектор речи. Добавляемое выносить в соседний модуль, файл `wake-flow.ts` не увеличивать.
