# 98. Сохранение настроек не перезапускает подключения; картинка снимка не остаётся в данных шага

1. По журналу времени серверы подключений (Confluence, Exchange) запускаются заново при каждом сохранении настроек, в том числе когда инструмент `speech_mode` переключает ответ вслух: `mcp.server.start` посреди ответа. Найти причину (`src/core/app.ts`, `saveConfig` и `reloadConfig`, менеджер серверов) и сделать: серверы перезапускаются только если изменились сами подключения (список, адрес, команда, аргументы, окружение, секрет); остальные изменения настроек применяются без перезапуска серверов. То же проверить для остальных частей, которые `reloadConfig` пересоздаёт (расписание, слежение, группы инструментов): пересоздавать только то, чьи настройки изменились.
2. `screen_look` (`src/core/tools/screen.ts`, `src/core/vision/look.ts`) кладёт байты снимка в `data` результата, чтобы сохранить файл. После сохранения байты из результата убрать: в `data` остаются источник и путь к файлу. Шаг навыка, подставляющий данные шага целиком, не должен получать картинку.

Тесты: сохранение настроек с изменением только голоса, характера или приложения не запускает и не останавливает серверы; изменение подключения перезапускает только его; результат `screen_look` не содержит байтов снимка, файл сохранён, событие снимка для ленты отправлено. `npm run typecheck`, `npx vitest run --maxWorkers=1` (проверки по одной, память машины ограничена), `npm run build`.

Не трогать окно ежа, разговор, запись, речь (`src/voice`, `src/renderer/pet`, `src/pet`, `src/main/pet-*`).
