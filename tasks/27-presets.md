# 27. Пресеты навыков и их установка

## Цель

В приложении есть набор готовых навыков-пресетов, которые человек ставит одним действием и при желании правит. Пресеты показывают, что умеет Тишка, и служат основой сценария демонстрации.

Окно галереи в эту задачу не входит — только файлы пресетов, их проверка и установка из ядра.

## Что сделать

### Файлы пресетов

Каталог `presets/`, формат `tishka-skill/1` (см. `docs/contracts.md`). Имена инструментов серверов Confluence и Exchange взять из их кода в `mcp-servers/`, имена встроенных инструментов — из `src/core`. Инструмент сервера записывается как `<имя подключения>__<инструмент>`; в пресетах имена подключений — `confluence` и `exchange`, и они перечислены в `requires`.

Уже есть `friday-morning` и `watch-page` — привести их к правилам ниже. Добавить:

| id | Название | Запуск | Что делает |
|---|---|---|---|
| `my-day` | Мой день | фразы «что у меня сегодня», «мой день»; вручную | встречи на сегодня из Exchange → запрос к модели: короткая сводка (сколько встреч, первая, окна между ними) → реплика и карточка-текст со списком встреч |
| `morning-brief` | Утренняя сводка | расписание: будни, 9:30 | то же, что «Мой день», но сам, без просьбы |
| `weekly-report` | Итог недели | фразы «итог недели», «оформи итог недели»; вход `notes` — заметки за неделю (обязательный) | запрос к модели: разложить заметки по разделам «Сделано», «В работе», «Планы», ничего не выдумывая; карточка-текст только с результатом |
| `draft-letter` | Письмо по шаблону | фразы «подготовь письмо», «напиши письмо»; входы `to`, `topic`, `points` | запрос к модели: текст вежливого короткого письма по теме и тезисам → ссылка на черновик письма из Exchange → реплика и карточка со ссылкой и текстом; письмо не отправляется |
| `meeting-invite` | Позвать на встречу | фразы «назначь встречу», «позови на встречу»; входы `who`, `topic`, `when` | ссылка на черновик встречи из Exchange → карточка со ссылкой |
| `page-changes` | Что изменилось на странице | фразы «что нового на странице», «что изменилось на странице»; вход `page_id` | версия и история страницы из Confluence → запрос к модели: кто и когда менял, коротко → карточка-текст |
| `standup-reminder` | Напоминание о планёрке | расписание: будни, 10:55 | реплика «Через пять минут планёрка» |

Правила для всех пресетов:

- адреса, номера страниц, имена людей — только через `inputs` с понятным описанием и разумным значением по умолчанию там, где оно возможно; в файлах нет настоящих адресов компании, имён и секретов (для примеров — домен `example.org`);
- реплика `say` — одно короткое предложение без цифр и латиницы, подробности — в `show`;
- у каждого пресета 2–4 фразы вызова (кроме запускаемых только по расписанию или наблюдению), заполнено `description` — одно предложение о пользе;
- `watch-page`: в реплике при изменении — карточка со ссылкой на страницу и номером новой версии.

### Установка из ядра

`src/core/skills/presets.ts`:

```ts
function listPresets(dir: string): Promise<{ id: string; name: string; description: string; requires: string[]; installed: boolean; valid: boolean; errors: string[] }[]>;
function installPreset(dir: string, id: string, store: SkillStore, opts?: { overwrite?: boolean }): Promise<{ ok: true } | { ok: false; error: string }>;
```

- `listPresets` читает все файлы `*.tishka.json` каталога, проверяет их той же проверкой, что и обычные навыки, и помечает уже установленные (по `id` в хранилище навыков).
- `installPreset` копирует пресет в хранилище навыков; если навык с таким `id` уже есть и `overwrite` не задан — ошибка «Навык уже установлен»; повреждённый пресет не ставится.
- Инструменты агента (источник `builtin`): `presets_list` и `preset_install { id }` — чтобы можно было сказать «покажи готовые навыки» и «поставь итог недели». Подключить в сборке ядра рядом с инструментами навыков; каталог пресетов передаётся в ядро параметром.
- В системное сообщение — одна строка: на просьбу показать, что Тишка умеет, или предложить готовое — посмотреть пресеты и показать их списком в карточке.

## Как проверить

Тесты `tests/presets.test.ts`:

- каждый файл из `presets/` проходит проверку навыка; `id` совпадает с именем файла; `id` не повторяются;
- каждый шаг с инструментом ссылается либо на встроенный инструмент, либо на инструмент подключения из `requires`; имена инструментов Confluence и Exchange существуют в коде серверов (сверить со списком инструментов сервера);
- все подстановки `{{inputs.x}}` и `{{steps.x…}}` ссылаются на объявленные входы и на шаги, стоящие раньше;
- в текстах `say` нет цифр и латиницы;
- в файлах нет адресов, кроме `example.org`;
- `listPresets` помечает установленные; `installPreset` ставит, не перезаписывает без `overwrite`, не ставит повреждённый файл;
- прогон каждого пресета исполнителем навыков с подставными инструментами и подставной моделью доходит до конца и отдаёт реплику.

`npm run typecheck`, `npm test`, `npm run build`.

## Не делать

Окно галереи, импорт и экспорт файлом из окна, правки серверов Confluence и Exchange, новые инструменты серверов.
