# 70. В строку ввода у ежа нельзя ввести текст

## Что не так

Строка ввода под ежом видна, но текст в неё не вводится: щелчок по полю не делает его активным.

## Где искать

- Окно ежа показывается без фокуса (`showInactive` в `src/main/pet-window.ts`); фокус окно получает только при вызове клавишей или щелчке по ежу (`wake` с источником `hotkey`/`click`, `focusWindow`). При появлении по имени, по запуску, по уведомлению, после ответа на текст из чата окно остаётся без фокуса, и щелчок по полю ввода его не активирует.
- Окно пропускает щелчки сквозь себя (`setIgnoreMouseEvents(true, { forward: true })`), а «интерактивность» включается по движению мыши (`src/renderer/pet/pet.ts`, `isInteractiveAt`/`setInteractive`): если состояние рассинхронизировалось (окно перезагружено, мышь уже стояла над полем в момент появления, поле появилось под неподвижной мышью), щелчок уходит в окно под ежом.
- Строка в свёрнутом виде (`setCollapsed` после `sleep` и `notify`) и в состоянии «занят» (`setBusy`): проверить, что щелчок по ней разворачивает и что «занят» снимается после ответа, ошибки и отмены.

## Что сделать

- Щелчок по строке ввода в любом состоянии ежа делает её рабочей: окно получает фокус, строка разворачивается, курсор стоит в поле, набранный текст появляется. Нажатие клавиш при фокусе в поле никогда не теряется.
- Интерактивность не зависит от того, двигалась ли мышь: при показе окна, при изменении раскладки и после перезагрузки окна состояние пересчитывается по текущему положению курсора (главный процесс знает положение курсора: `screen.getCursorScreenPoint()`), либо область строки ввода принимает щелчки всегда, пока строка видна.
- Появление, при котором человек собирается писать (щелчок по значку возле часов, запуск приложения с показом ежа, горячая клавиша), сразу ставит фокус в поле. Появление по имени и по уведомлению фокус у текущего окна не отбирает, но первый же щелчок по полю его даёт.
- Пока ёж «думает» или «работает», в поле можно печатать (отправка встаёт в очередь, как сейчас); поле не блокируется атрибутом `disabled`.

## Как проверить

Тесты: щелчок по свёрнутой строке разворачивает её и запрашивает фокус окна; щелчок по полю при окне без фокуса вызывает запрос фокуса; пересчёт интерактивности при показе окна с курсором над полем; «занят» снимается после `reply`, `error`, `idle`; поле не получает `disabled`.

`npm run typecheck`, `npx vitest run --maxWorkers=2`, `npm run build`. В отчёте назвать найденную причину.

## Не делать

Не менять расчёт положения и размеров окна (`src/pet/layout.ts`, `dragBy`). Не трогать `src/core`, `src/voice`, `src/renderer/chat`, `src/renderer/settings`. Файлы не длиннее 200 строк. Стили только в css.
