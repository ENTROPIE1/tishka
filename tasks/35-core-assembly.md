# 35. Сборка ядра и подключение к главному процессу

## Цель

Все готовые части ядра собираются в одно целое: фраза пользователя проходит путь «выбор навыка или агент — инструменты — ответ», расписание и наблюдения работают, серверы MCP подключаются. После этой задачи с Тишкой можно переписываться в терминале, а главный процесс Electron отвечает на текст из окна.

## Что сделать

`src/core/app.ts` — без импорта `electron`:

```ts
interface CoreDeps {
  dataDir: string;                 // каталог данных пользователя
  presetsDir: string;              // каталог presets/
  appRoot: string;                 // корень приложения, от него считаются относительные пути серверов MCP
  secrets: SecretStore;
  events: EventBus;
  openExternal(url: string): Promise<void>;
  showPanel(panel: Panel): void;
  now: () => Date;
  fetch?: typeof fetch;            // для тестов
}

function createTishkaCore(deps: CoreDeps): {
  start(): Promise<void>;
  stop(): Promise<void>;
  handleUserText(text: string): Promise<Reply>;
  config(): Config;
  mcpStatus(): McpStatus[];
  reloadConfig(): Promise<void>;   // перечитать config.json и переподключить серверы MCP
};
```

Порядок в `start()`:

1. `loadConfig(dataDir)`.
2. Хранилище навыков в `dataDir/skills`, затем `loadPresets(presetsDir)`.
3. Реестр инструментов, встроенные инструменты (`registerBuiltinTools`).
4. Клиент моделей: адрес из настроек, ключ из секрета `DKS_API_KEY`.
5. Исполнитель навыков; его `ask` — один запрос к модели `config.llm.model` без инструментов, ответ текстом.
6. Состояние триггеров `dataDir/triggers.json`, планировщик, наблюдатель, инструменты напоминаний (`registerTriggerTools`), инструменты навыков (`registerSkillTools`).
7. Агент: модель из настроек, характер из `config.persona`.
8. Маршрутизатор (`createRouter`), `refreshSkills()`.
9. Запуск планировщика и наблюдателя.
10. Подключение серверов MCP из настроек. Оно не задерживает `start()`: идёт в фоне, после подключения каждого сервера вызывается `refreshSkills()`. Сбой сервера не мешает работе, статус виден в `mcpStatus()`.

Правила:

- Для серверов с `transport: 'stdio'` относительные пути в `args` (начинаются не с `/`, не с буквы диска и не с `-`) считаются от `appRoot`. Команда `node` заменяется на `process.execPath` с переменной окружения `ELECTRON_RUN_AS_NODE=1`, чтобы сервер запускался и там, где Node.js не установлен отдельно.
- `handleUserText`: событие `listen.end` с текстом, затем `router.handle(text)`, в конце событие `idle`. Исключение превращается в `Reply` с понятной фразой и `mood: 'confused'` и в событие `error`; наружу исключение не выходит. Пока обрабатывается одна фраза, следующая ждёт своей очереди.
- `stop()` останавливает планировщик и наблюдатель и закрывает серверы MCP. Повторный `stop()` безопасен.
- Секреты не попадают в события и в тексты ошибок.

`src/main/index.ts`:

- создаёт ядро с каталогом `app.getPath('userData')`, каталогом пресетов и корнем приложения (в разработке — корень проекта, в сборке — `app.getAppPath()`), `openExternal` из `shell`;
- текст из окна (`sendUserText`) передаёт в `core.handleUserText`;
- при выходе из приложения вызывает `core.stop()`;
- `showPanel` пока отправляет событие `reply` с этой панелью и пустым `say` не нужно — достаточно оставить пустую функцию: панели приходят в составе ответа.

Скрипт `scripts/chat.ts` — переписка с Тишкой в терминале без Electron:

- каталог данных — из аргумента `--data <путь>`, по умолчанию временный;
- секреты — в памяти, значения берутся из переменных окружения с теми же именами (`DKS_API_KEY`, `CONFLUENCE_TOKEN`, `EXCHANGE_PASSWORD`);
- `openExternal` только печатает ссылку, не открывая её, если не указан ключ `--open`;
- каждая введённая строка уходит в `handleUserText`; печатаются `say`, заголовок и содержимое панели, а также события `tool.start`, `notify` и `error` по мере появления;
- при запуске печатает статус серверов MCP и число навыков;
- команда `/exit` завершает работу с вызовом `stop()`.

Запуск: `npx tsx scripts/chat.ts [--data путь] [--open]`.

## Как проверить

Тесты `tests/app.test.ts` с подменой `fetch` и временным каталогом (перед удалением каталога вызывать `stop()` и удалять через `rm` с повторами):

- После `start()` в пустом каталоге данных появились пресеты, `config()` возвращает значения по умолчанию.
- Фраза «утро пятницы» запускает пресет: `openExternal` вызван для его ссылок, модель не вызывалась.
- Фраза без подходящего навыка уходит модели; ответ через инструмент `reply` возвращается как `Reply`, событие `reply` отправлено, в конце событие `idle`.
- Модель вызывает `create_reminder` — напоминание появляется в `triggers.json`.
- Нет ключа `DKS_API_KEY` → `handleUserText` возвращает `Reply` с `mood: 'confused'`, исключения нет.
- Сервер MCP с несуществующей командой в настройках: `start()` завершается, остальные функции работают, в `mcpStatus()` у сервера состояние `error`.
- Две фразы подряд обрабатываются по очереди, а не одновременно.
- После `stop()` таймеры остановлены: тест завершается без висящих ресурсов.

Проверка вручную: `npx tsx scripts/chat.ts` с ключом в `DKS_API_KEY` — на «привет» приходит ответ, на «утро пятницы» печатаются ссылки пресета.

## Не делать

Окна чата и питомца, экран настроек, голос. Новые инструменты.
