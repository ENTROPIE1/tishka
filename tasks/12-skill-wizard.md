# 12. Создание навыка в диалоге

## Цель

Пользователь словами объясняет, что нужно делать, Тишка задаёт уточняющие вопросы и сохраняет готовый навык. Это главная функция продукта: навыку учат, а не программируют.

## Что сделать

`src/core/skills/tools.ts` — `registerSkillTools(registry, deps)`:

```ts
interface SkillToolsDeps {
  store: { list(): Promise<Skill[]>; get(id: string): Promise<Skill | undefined>; save(skill: Skill): Promise<void>; remove(id: string): Promise<void> };
  registry: ToolRegistry;        // для списка известных инструментов
  events: EventBus;
}
```

| Инструмент | Аргументы | Что делает | readOnly |
|---|---|---|---|
| `save_skill` | `skill: object` | Проверяет навык через `validateSkill` со списком имён инструментов из реестра (без `skill__...` и без самих инструментов этой таблицы) и сохраняет. При ошибках возвращает `ok: false` и все ошибки списком в `content`, чтобы модель исправила и повторила | false |
| `list_skills` | — | Список навыков: `id`, название, фразы, вид триггера | true |
| `get_skill` | `id: string` | Полный файл навыка | true |
| `delete_skill` | `id: string` | Удаляет навык | false |

- После успешного `save_skill` отправляется событие `skill.saved`.
- Если навык с таким `id` уже есть, он заменяется: так работает правка навыка.
- В `content` успешного ответа — короткая строка «Навык сохранён: <название>».

`src/core/agent/skill-guide.ts` — текст для системного сообщения, функция `skillGuide(tools: ToolDef[]): string`. В тексте:

1. Когда пользователь просит научиться, запомнить, делать что-то регулярно или следить за чем-то — это создание навыка.
2. Порядок: понять, что делать и когда; задать недостающие вопросы по одному, не больше трёх; коротко пересказать, что получится; после согласия вызвать `save_skill`.
3. Что уточнять: по какой фразе или когда запускать; что именно открыть, прочитать или проверить (адрес, номер страницы); что сказать в конце.
4. Формат навыка: поля из `docs/contracts.md`, три вида триггера, три вида шага, подстановки.
5. Два полных примера JSON: навык по фразе с `open_urls` и навык с триггером `watch`.
6. Правила: `id` латиницей через дефис; в шагах только инструменты из переданного списка; секреты в навык не пишутся; если нужного инструмента нет — честно сказать, что так пока не умеет, и не сохранять.
7. Если `save_skill` вернул ошибки — исправить и вызвать снова, пользователю ошибки проверки не пересказывать.

Список доступных инструментов для шагов подставляется в текст: имя и описание каждого.

Подключение: `src/core/agent/prompt.ts` принимает этот текст дополнительным разделом. Сигнатуру `createAgent` из задачи 06 не менять; если разделу нужен список инструментов, он берётся из реестра в момент обращения к модели.

Скрипт `scripts/check-wizard.ts`: ключ из `DKS_API_KEY`, настоящая модель, реестр со встроенными инструментами и подставным `confluence__get_page_version`, хранилище во временном каталоге. Проигрывает диалог из трёх реплик пользователя:

1. «Научись следить за страницей в конфлюенсе»
2. «Страница 123456, проверяй каждые две минуты»
3. «Да, сохраняй»

и печатает ответы Тишки и сохранённый навык. Запуск: `npx tsx scripts/check-wizard.ts [имя модели]`.

## Как проверить

Тесты `tests/skill-tools.test.ts`:

- `save_skill` с правильным навыком сохраняет его и отправляет `skill.saved`.
- `save_skill` с неизвестным инструментом в шаге возвращает `ok: false`, в `content` названа ошибка, навык не сохранён, события нет.
- `save_skill` с полем `token` отклоняется.
- Повторный `save_skill` с тем же `id` заменяет навык.
- `list_skills`, `get_skill`, `delete_skill` работают; `get_skill` для неизвестного `id` возвращает `ok: false`.
- `skillGuide` содержит имена переданных инструментов и оба примера, и оба примера проходят `validateSkill`.

Проверка вручную: `scripts/check-wizard.ts` заканчивается сохранённым навыком с триггером `watch`, инструментом `confluence__get_page_version` и `page_id` 123456.

## Не делать

Окно редактора навыков, импорт и экспорт, запуск навыка по фразе.
