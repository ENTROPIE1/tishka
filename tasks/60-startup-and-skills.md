# 60. Запуск ядра, переподключение серверов, время в навыках

Находки 3, 5, 7, 8 из `tasks/reports/54-core.md`.

## Что сделать

- `src/core/mcp/manager.ts`: подключения к одному и тому же серверу идут по очереди (цепочка по имени сервера); второй вызов дожидается первого и закрывает его подключение. Незакрытых подключений и лишних процессов не остаётся, в том числе после `closeAll`.
- `src/core/skills/validate.ts`: поле `trigger.at` должно разбираться как дата и время, иначе ошибка проверки с понятным текстом. `src/core/triggers/scheduler.ts`: уже сохранённый навык с неразборчивым `at` один раз даёт событие `error` с названием навыка и больше не проверяется.
- `src/core/app.ts`, `start()`: сбой необязательного шага (история, пресеты) не оставляет ядро «не проснувшимся»: шаг изолирован, пользователю уходит событие `error` с объяснением, остальные шаги выполняются. Если упал обязательный шаг — повторный `start()` возможен.
- `docs/contracts.md`: добавить событие `memory.changed` в список событий.

## Как проверить

Тесты: два одновременных подключения к одному серверу — одно живое подключение, второе закрыто; навык с `at: 'завтра утром'` не проходит проверку; сохранённый такой навык даёт одно событие `error`; сбой чтения истории при старте — ядро отвечает на реплики, событие `error` отправлено; повторный `start()` после сбоя.

`npm run typecheck`, `npx vitest run --maxWorkers=2`, `npm run build`.

## Не делать

Не трогать `src/renderer`, `src/main`, `src/core/agent`, `src/core/llm`. В `src/core/app.ts` менять только `start()`. Файлы не длиннее 200 строк.
