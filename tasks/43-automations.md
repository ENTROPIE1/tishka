# 43. Экран «Автоматизации» и тихая фоновая работа

## Цель

1. Человек видит все свои навыки и автоматизации в одном месте: что есть, что каждая делает, когда запускается, работает ли сейчас — и может запустить, приостановить, поправить, удалить, поставить готовую.
2. Фоновые проверки (наблюдения, расписание) не занимают Тишку: во время них он остаётся свободен и слушает человека.

Заменяет строку 19 плана (галерея пресетов, импорт и экспорт).

## Дефект: фоновая проверка «занимает» Тишку

Наблюдение вызывает инструмент через общий реестр, реестр шлёт события `tool.start` и `tool.end`, окно-питомец по ним переходит в состояние «работает», затем «думает» — и остаётся в нём, потому что реплики после фоновой проверки нет. В облачке висит «использует инструмент confluence__get_page_version», режим разговора считает, что Тишка думает, и не слушает.

Что сделать:

- `ToolRegistry.call(name, args, opts?: { background?: boolean })`: при `background: true` события `tool.start` и `tool.end` не отправляются (вместо них — `background.tick` с именем навыка, для экрана автоматизаций и журнала). Наблюдения и проверки расписания вызывают инструменты с этим признаком. Шаги навыка, запущенного человеком, идут как раньше. Поле добавлено в `docs/contracts.md`.
- Когда наблюдение заметило изменение и запускает шаги навыка — это уже не фон: Тишка появляется с событием `notify`, шаги идут с обычными событиями и заканчиваются репликой.
- Страховка в `src/pet/state.ts`: состояния `thinking` и `working` не могут длиться дольше 90 секунд без новых событий — по истечении переход в `idle`. Режим разговора после такого перехода снова слушает.
- Проверка, что наблюдение с `everyMinutes: 15` действительно вызывает инструмент раз в 15 минут, а не чаще (тест на подменном времени, включая перезапуск приложения: после перезапуска первая проверка — не раньше, чем через минуту после старта, и не чаще срока).

## Изменение контракта

В `Skill` добавлено необязательное поле `enabled?: boolean` (нет поля — включён). Выключенный навык не запускается по расписанию и наблюдению и не предлагается агенту как инструмент; запуск вручную с экрана остаётся.

## Что сделать

### Описание навыка человеческим языком

`src/core/skills/describe.ts` — чистая функция:

```ts
function describeSkill(skill: Skill): {
  title: string;        // название
  summary: string;      // description навыка
  when: string;         // «По фразе: “итог недели”, “оформи итог недели”» / «По расписанию: по будням в 9:30» / «Наблюдение: каждые 15 минут проверяет страницу»
  does: string[];       // шаги простыми словами: «Смотрит встречи в календаре», «Просит модель собрать сводку», «Говорит и показывает карточку»
  needs: string[];      // подключения из requires: «Confluence», «Exchange»
  inputs: string[];     // что спросит: «Заметки за неделю»
  kind: 'phrase' | 'schedule' | 'watch';
};
```

- Расписание cron переводится в слова для частых случаев: каждый день, по будням, по конкретным дням недели, в заданное время, каждые N минут или часов; непонятное выражение показывается как есть с пометкой «по расписанию».
- Шаг с инструментом описывается по описанию инструмента из реестра (первое предложение), если инструмент известен; иначе — «Вызывает <имя>». Шаг `ask` — «Просит модель: <первые 60 символов>…», шаг `say` — «Говорит: <текст>».

### Состояние запусков

Ядро хранит для каждого навыка (в том же файле состояния, что расписание и наблюдения): время последнего запуска, его итог (`ok` / текст ошибки), время последней фоновой проверки, время следующей проверки или запуска, число срабатываний. `core.skills.overview(): SkillOverview[]` отдаёт навык, его описание и это состояние.

### Экран

Новый экран основного окна «Автоматизации» в полосе навигации (между «Чат» и «Подключения»), модуль `src/renderer/chat/automations/` (несколько файлов, каждый не длиннее 200 строк), стили в отдельном css. Экран возвращает `{ refresh() }`, если так устроены соседние экраны, и обновляется по событиям `background.tick`, сохранения и удаления навыка.

Две вкладки:

**Мои** — карточки навыков, сгруппированные: «Работают сами» (расписание и наблюдения), «По просьбе» (по фразе). В карточке:

- название, описание, значок вида (часы — расписание, глаз — наблюдение, реплика — по фразе);
- строка «Когда» и список «Что делает» из `describeSkill`; нужные подключения — метками, красная метка, если подключение не настроено или не подключено;
- для работающих сами: состояние цветной точкой («работает», «приостановлен», «ошибка»), «последняя проверка 2 минуты назад», «следующая через 13 минут», «сработал 3 раза, последний — сегодня в 10:22»;
- кнопки: «Запустить сейчас» (если нужны входные данные — спрашивает их в небольшой форме), переключатель «Включён», «Изменить», «Экспорт», «Удалить» (с подтверждением);
- «Изменить» — форма: название, описание, фразы вызова, для расписания — время и дни недели, для наблюдения — период в минутах, значения входных данных по умолчанию. Шаги в форме не правятся — показаны списком, с подсказкой «Чтобы изменить шаги, попросите Тишку: “измени навык …”». Сохранение проходит обычную проверку навыка, ошибки показываются у полей.
- Пустое состояние: «Навыков пока нет. Скажите Тишке “научись…” или поставьте готовый на вкладке “Готовые”».

**Готовые** — пресеты из `listPresets`: название, описание, «Когда» и «Что делает», метки подключений; кнопка «Поставить» (у установленных — «Установлен» и «Поставить заново»). Кнопка «Импорт из файла» — выбор файла `*.tishka.json`, проверка, показ описания и подтверждение перед установкой; файл с ошибками не ставится, ошибки показываются.

Экспорт и импорт — через диалоги главного процесса; в файле экспорта нет секретов и состояния запусков.

### Связь с Тишкой

- После сохранения навыка в диалоге карточка «Навык сохранён» получает кнопку-ссылку «Открыть в автоматизациях» (открывает экран и подсвечивает карточку).
- Инструмент агента `skills_overview` (источник `builtin`): список навыков с описанием и состоянием, чтобы на «какие у меня автоматизации» и «что ты сейчас отслеживаешь» Тишка отвечал по делу; в системное сообщение — одна строка об этом.

## Как проверить

Тесты:

- фоновый вызов инструмента не порождает `tool.start` и `tool.end`, порождает `background.tick`; после фоновой проверки состояние окна-питомца остаётся `idle` или `hidden`;
- сработавшее наблюдение порождает `notify` и реплику;
- `thinking` дольше 90 секунд без событий → `idle`;
- наблюдение раз в 15 минут: за час на подменном времени — 4 вызова; после «перезапуска» — без лишнего вызова раньше срока;
- `describeSkill` для каждого пресета из `presets/`: непустые `when` и `does`, верный `kind`; cron «30 9 * * 1-5» → «по будням в 9:30»;
- выключенный навык не запускается по расписанию и не попадает в инструменты агента;
- экран (jsdom): группы, состояние, переключатель вызывает сохранение с `enabled: false`, удаление спрашивает подтверждение, форма «Изменить» сохраняет фразы и период, ошибка проверки показана;
- установка пресета и импорт файла; повреждённый файл не ставится;
- экспорт не содержит состояния запусков.

`npm run typecheck`, `npm test`, `npm run build`.
