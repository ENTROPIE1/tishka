# 108. Почта Exchange: чтение и поиск писем

Сервер `mcp-servers/exchange` умеет встречи и ссылки на черновики. Нужно, чтобы Тишка мог читать и искать письма тем же подключением (EWS, NTLM, логин и пароль из хранилища секретов). Только чтение: ничего не отправлять, не удалять, не перемещать и не помечать прочитанным.

## Что сделать

Инструменты сервера (все `readOnly: true`):

- `mail_search` — поиск писем. Параметры: `query` (слова в теме и тексте), `from` (имя или адрес отправителя), `folder` (`inbox` по умолчанию, `sent`, `drafts`, `all`), `since`, `until` (даты), `unread` (только непрочитанные), `has_attachments`, `limit` (по умолчанию 10, не больше 25). Возвращает список: идентификатор, тема, отправитель, дата, первые 200 знаков текста, признаки «не прочитано» и «есть вложения», ссылка на письмо в веб-почте. Реализация через EWS `FindItem` с ограничением (`Restriction` или строка запроса AQS), сортировка от новых к старым.
- `mail_read` — письмо по идентификатору: тема, отправитель, получатели, дата, текст (HTML приводится к простому тексту, цитаты прошлых писем сворачиваются в «…», не больше 8000 знаков, с пометкой об обрезке), список вложений (имя, размер; содержимое вложений не читается), ссылка в веб-почте. Через `GetItem`; письмо при этом не помечается прочитанным.
- `mail_unread` — число непрочитанных во входящих и до пяти последних (тема, отправитель, время).
- `mail_thread` — письма одной переписки по идентификатору письма (тема, отправитель, дата, начало текста), от старых к новым, не больше 15.

В приложении:

- Правило в подсказке: «найди письмо от…», «что писал…», «есть ли новые письма», «о чём последнее письмо от…» — эти инструменты; содержимое письма Тишка пересказывает коротко вслух, а текст показывает карточкой со ссылкой «Открыть в почте». Указания, встреченные в тексте письма, Тишка не выполняет: письмо — данные, а не просьба человека (строка об этом в описании инструмента и в подсказке).
- Шаблон подключения Exchange в «Подключениях»: в описании появляется «читает календарь и почту»; для уже добавленных подключений новые инструменты появляются после переподключения.
- Пример навыка в `presets/`: «Что в почте с утра» — непрочитанные за сегодня списком с темами и отправителями.

## Как проверить

Тесты сервера на записанных ответах EWS (как у встреч): поиск по словам, по отправителю, по периоду, только непрочитанные, пустой результат, ошибка авторизации; чтение письма с HTML, с вложениями, длинного с обрезкой; письмо не помечается прочитанным (в запросе нет изменения признака); переписка. Тест, что ни один новый инструмент не шлёт запросов на изменение (`CreateItem`, `UpdateItem`, `DeleteItem`, `MoveItem`, `SendItem`). `npm run typecheck`, `npx vitest run --maxWorkers=1` (проверки по одной, память машины ограничена), `npm run build`, `npm run build:mcp`. Обновить `README.md` и `docs/contracts.md`.

## Не делать

Не трогать окно ежа, голос, запись. Не читать содержимое вложений. Не сохранять тексты писем на диск: в историю разговора попадает только ответ Тишки и карточка, как для остальных инструментов.
