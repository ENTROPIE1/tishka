# 65. Шлюзы с форматом Responses

## Цель

Некоторые шлюзы не поддерживают `/chat/completions` и принимают только формат OpenAI Responses: `POST <адрес>/responses`. Тишка должен уметь работать через такой шлюз: текст, вызов инструментов, картинки.

## Что сделать

- Настройки: поле `llm.api` со значениями `'chat'` (по умолчанию) и `'responses'`. Разбор настроек: неизвестное значение → `'chat'`. `docs/contracts.md` и `src/core/types.ts` — описать поле.
- `src/core/llm`: клиент модели при `llm.api === 'responses'` отправляет запрос в формате Responses и приводит ответ к тому же внутреннему виду, что и для `chat` (текст, вызовы инструментов с идентификаторами, причина остановки). Остальной код (агент, зрение) о формате не знает. Преобразование — отдельный модуль (`responses-format.ts`), чистые функции с тестами:
  - системное сообщение → поле `instructions`; остальные сообщения → массив `input`;
  - сообщение пользователя: `{role:'user', content:[{type:'input_text', text}]}`; картинка (`image_url`) → `{type:'input_image', image_url:'data:...'}`;
  - сообщение ассистента с текстом → `{role:'assistant', content:[{type:'output_text', text}]}`;
  - вызов инструмента ассистентом → элемент `{type:'function_call', call_id, name, arguments}` (аргументы строкой JSON);
  - результат инструмента (`role:'tool'`) → `{type:'function_call_output', call_id, output}`;
  - инструменты: `{type:'function', name, description, parameters}` (плоский вид, без вложенного `function`);
  - `tool_choice` передаётся как есть (`'auto'`, `'required'`); `max_tokens` → `max_output_tokens`;
  - в запросе `store: false`, `stream: false`.
  - Ответ: массив `output`; элементы `type:'message'` → текст собирается из частей `output_text`; элементы `type:'function_call'` → вызовы инструментов (`call_id`, `name`, `arguments`); элементы `reasoning` пропускаются. Пустой `output` или неожиданный вид → та же ошибка «непонятный ответ», что и сейчас.
  - Если шлюз вернул поток событий (тип содержимого `text/event-stream`), несмотря на `stream: false`: читать события до `response.completed` и брать итоговый объект `response` из него.
- Повторы, срок ожидания, разбор ошибок шлюза — общие с форматом `chat`.
- Проверка шлюза (`src/core/llm/check.ts`): принимает формат; при `'responses'` пробный запрос идёт на `/responses`. Если пробный запрос в формате `chat` получил ошибку, в тексте которой сказано, что `/chat/completions` не поддерживается, — сообщение «Шлюз не поддерживает формат chat. Выберите формат Responses».
- Раздел «Модель» в настройках: переключатель «Формат запросов» (`Chat Completions` / `Responses`), сохраняется вместе с остальными полями, участвует в проверке.
- `README.md`, раздел про другой шлюз: одно предложение о формате.

## Как проверить

Тесты: преобразование каждого вида сообщения и инструментов; разбор ответа с текстом, с двумя вызовами инструментов, с `reasoning`; поток событий вместо JSON; полный ход агента через поддельный шлюз Responses (вопрос → вызов инструмента → результат → ответ через `reply`); запрос с картинкой; проверка шлюза в обоих форматах; настройки без поля `api` читаются как `chat`.

`npm run typecheck`, `npx vitest run --maxWorkers=2`, `npm run build`.

## Не делать

Не менять поведение формата `chat`. Не трогать `src/voice`, `src/renderer/pet`, `src/renderer/chat`. Файлы не длиннее 200 строк. Стили только в css.
