# 54. Поиск ошибок по области кода

## Цель

Найти настоящие ошибки поведения в указанной области кода (область названа в указании к запуску). Ничего не исправлять: результат — отчёт.

## Что искать

- Гонки и порядок событий: повторный запуск до завершения предыдущего, ответ пришёл после отмены, обработчик сработал после `dispose`, состояние не сброшено после ошибки.
- Зависания: обещание, которое никогда не завершится; ожидание без предела по времени; флаг «занят», который не снимается при исключении.
- Утечки: подписки, таймеры, слушатели, потоки микрофона, которые не снимаются.
- Потерянные ошибки: `catch` без сообщения пользователю там, где он ждёт ответа; пользователь остаётся без объяснения.
- Граничные значения: пустая строка, очень длинный текст, отсутствующее поле в настройках или в ответе модели, ноль, отрицательное число, повреждённый файл данных.
- Расхождение с `docs/contracts.md`.

Не считаются находками: стиль, названия, «можно было бы лучше», отсутствие тестов, длина файла.

## Как работать

1. Прочитать файлы области и их тесты.
2. Для каждого подозрения проследить по коду, действительно ли оно достижимо. Недостижимое — выбросить.
3. Где возможно, подтвердить тестом: временно написать тест, который показывает ошибку, запустить, убедиться, что он падает по этой причине. Текст теста перенести в отчёт, сам тест из репозитория удалить.
4. Записать отчёт в `tasks/reports/54-<область>.md`.

## Отчёт

Находки по убыванию важности, не больше десяти. Для каждой:

- файл и строка;
- что должно произойти у пользователя, чтобы ошибка проявилась (по шагам);
- что он увидит;
- подтверждено тестом (текст теста) или только чтением кода;
- как исправить, одним-двумя предложениями.

В конце — что просмотрено и ошибок не найдено.

## Не делать

- Не менять код в `src/`, не оставлять новых тестов.
- Не запускать приложение. `npm install` не запускать.
