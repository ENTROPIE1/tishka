# 89. Адрес службы распознавания в настройках

Сейчас адрес службы распознавания (`voice.sttUrl`) в интерфейсе не задаётся; чтобы пользоваться службой на другой машине через туннель, приходится очищать поля «Программа» и «Модель».

## Что сделать

- Экран «Голос» → «Служба распознавания»: переключатель из двух вариантов — «Запускать на этом компьютере» (поля «Программа» и «Модель», как сейчас) и «Готовая служба по адресу» (поле адреса, по умолчанию `http://127.0.0.1:8178`). Выбор и адрес сохраняются в настройках (`voice.stt.mode`: `local` или `remote`, `voice.sttUrl`); пути программы и модели при выборе готовой службы не стираются, а просто не используются.
- При выборе готовой службы приложение ничего не запускает и не останавливает чужой процесс; состояние службы определяется проверкой адреса. Смена варианта или адреса применяется сразу: локальная служба останавливается при переходе на готовую, запускается при переходе обратно.
- Кнопка «Проверить» рядом с адресом: отвечает ли служба и за сколько миллисекунд.
- Старые настройки без поля `mode`: пустые пути — `remote`, заполненные — `local`.
- `README.md`, раздел про туннель: шаг «очистить поля» заменить на «выбрать „Готовая служба по адресу“».

## Как проверить

Тесты: разбор настроек со старым и новым видом; переключение вариантов останавливает и запускает локальную службу; при `remote` процесс не запускается; проверка адреса возвращает время ответа или причину. `npm run typecheck`, `npx vitest run --maxWorkers=1`, `npm run build`.

## Не делать

Не трогать окно ежа, разговор и запись (`src/renderer/pet`, `src/pet`, `src/voice/wake-flow.ts`, `src/voice/vad.ts`). Раздел «Микрофон» того же экрана не менять — им занята другая задача.
