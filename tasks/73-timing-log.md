# 73. Журнал времени запуска и голосовой цепочки

После запуска приложения первую голосовую реплику приходится ждать около 30 секунд; где теряется время, по имеющимся данным установить нельзя. Нужен журнал с отметками времени.

## Что сделать

- Модуль журнала времени в `src/main` (например `timing-log.ts`): функция `mark(event: string, details?: Record<string, string | number | boolean>)` дописывает строку в файл `timing.log` в каталоге данных приложения (`app.getPath('userData')`). Формат строки: время ISO, миллисекунды от старта процесса, миллисекунды от предыдущей отметки, имя события, детали в виде `ключ=значение`. Запись не блокирует работу (ошибки записи глотаются), при размере файла больше 1 МБ он начинается заново. При старте приложения пишется строка-разделитель с версией.
- Текст реплик, ключи, адреса с учётными данными в журнал не писать: только имена событий, длительности, размеры, коды ответов.
- Отметки в главном процессе: старт процесса; готовность приложения (`app.whenReady`); создание и первый показ окна ежа и основного окна; запуск процесса службы распознавания, каждая неудачная проверка готовности (с причиной), готовность службы; регистрация горячей клавиши; запуск серверов подключений (начало и готовность каждого); начало и конец запроса распознавания (длительность, размер звука, код ответа или причина сбоя); начало и конец запроса к модели (длительность, число шагов); начало и конец запроса синтеза речи.
- Отметки из окон (ёж и чат) через один новый канал preload `timingMark(event, details)`: запрос доступа к микрофону и его получение; начало прослушивания имени; начало записи фразы; обнаружение речи; конец фразы и отправка на распознавание; получение текста; показ ответа; начало и конец воспроизведения речи.
- В разделе «Приложение» настроек — кнопка «Открыть журнал времени», открывает файл в программе по умолчанию.
- Просмотреть код запуска и голосовой цепочки и в отчёте перечислить места, где первая реплика после запуска может ждать десятки секунд (ожидания с таймаутом 30 секунд, последовательные ожидания готовности, повторные попытки). Найденное не исправлять, только перечислить с именами файлов и строк.

## Как проверить

Тесты: формат строки, отсчёт от старта и от предыдущей отметки, обрезка файла, отсутствие исключений при сбое записи; канал из окна доходит до журнала. `npm run typecheck`, `npx vitest run --maxWorkers=2`, `npm run build`.

## Не делать

Не менять поведение запуска и голоса. Не писать в журнал содержимое реплик и секреты. Файлы не длиннее 200 строк; если файл с отметками упирается в предел, выносить отметки в соседний модуль.
