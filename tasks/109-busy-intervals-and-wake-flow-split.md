# 109. Отрезки занятости Тишки и разбор `wake-flow.ts`

Правило времени (задача 97) отбрасывает запись, начатую, пока Тишка думал или говорил. Сейчас помнится только последний отрезок занятости: фраза, начатая во время обдумывания, может пройти как реплика, если между обдумыванием и речью был короткий простой. Файл `src/voice/wake-flow.ts` вырос до 430 строк при правиле 200.

## Что сделать

- Модуль `src/voice/busy-intervals.ts`: хранит отрезки занятости за последние 2 минуты (начало, конец, причина: обдумывание, речь, работа), склеивает отрезки с промежутком меньше 1,5 с, отвечает на вопрос «пересекается ли запись, начатая в момент T, с занятостью». Старые отрезки удаляются сами.
- `wake-flow.ts` пользуется модулем вместо одного запомненного отрезка. Поведение, закреплённое тестами и сценариями задач 92, 97, 100, не меняется.
- Разобрать `wake-flow.ts` на модули не длиннее 200 строк по смыслу: приём отрезка и решение (вызов, стоп, реплика, отбросить), ведение разговора (окно ожидания, таймер тишины), связь с окном ежа. Набор взаимозависимых флагов заменить явным состоянием (`idle`, `summoned`, `listening`, `busy`, `speaking`) с одной функцией перехода, покрытой тестами. Внешний интерфейс модуля сохранить.

## Как проверить

Тесты модуля отрезков: один отрезок, два с коротким промежутком склеиваются, с длинным — нет, устаревание, запись до, во время и после. Сценарий в `tests/scenarios`: фраза начата во время обдумывания, между обдумыванием и речью простой 0,5 с — фраза отброшена. Все существующие сценарии и тесты проходят без ослабления. `npm run typecheck`, `npm run test:scenarios`, `npx vitest run --maxWorkers=1` (проверки по одной, память машины ограничена), `npm run build`.

## Не делать

Не менять пороги, длину отрезков, тексты реплик. Не трогать синтез речи и экран настроек.
