# 53. Память службы распознавания входит в предел памяти

## Цель

Сейчас наблюдение за памятью (`src/main/memory-watch.ts`) сравнивает с пределом только память процессов приложения: в `src/main/index.ts` передаётся `sttMb: 0`. Служба распознавания, которую приложение запускает само, в расчёт не входит. Нужно считать её тоже.

## Что сделать

- `src/voice/stt-service.ts`: метод `pid(): number | undefined` — идентификатор запущенного приложением процесса службы; `undefined`, если служба чужая (поля программы и модели пусты) или не запущена.
- Новый модуль `src/main/process-memory.ts`: по идентификатору процесса возвращает занятую память в мегабайтах. Windows: `tasklist /FI "PID eq N" /FO CSV /NH`, разбор строки (число с разделителями разрядов — пробел, неразрывный пробел, запятая, точка — и «K»/«КБ»). Запуск команды — через внедряемую функцию, чтобы тесты не запускали настоящую. Ошибка, нет процесса, другая система — 0. Вызов асинхронный; модуль хранит последнее значение и обновляет его не чаще раза в 30 секунд (`current(): number`, `refresh(): Promise<void>`).
- `src/main/index.ts`: `sttMb` берётся из этого модуля; обновление запускается перед каждой проверкой памяти (по тому же интервалу).
- `src/main/memory-watch.ts`: с пределом сравнивается сумма `appMb + sttMb`; в журнал пишутся обе части. Перезагрузка окон делается только если над пределом сама память приложения выросла; остальное поведение (ожидание, одно уведомление, перезапуск не чаще раза в час, не во время разговора) без изменений. При перезапуске служба распознавания останавливается, как сейчас.
- `src/core/types.ts`: комментарий у `memoryLimitMb` — «предел памяти приложения вместе со службой распознавания». Подпись поля на экране настроек (`src/renderer/settings/app-section.ts`) — то же уточнение коротко.
- `docs/contracts.md`: поправить описание `app.memoryLimitMb`.

## Как проверить

Тесты:
- разбор вывода `tasklist`: `"whisper-server.exe","1234","Console","1","612 340 K"`, вариант с неразрывным пробелом, с запятой, строка «INFO: No tasks…», пустой вывод, ошибка запуска → 0;
- обновление не чаще раза в 30 секунд (поддельное время);
- наблюдение за памятью: приложение 900 + служба 700 при пределе 1500 → срабатывает; 900 + 0 → нет; чужая служба (`pid` нет) → считается 0;
- `pid()` у службы: есть после запуска, `undefined` после остановки и для чужой службы.

`npm run typecheck`, `npx vitest run --maxWorkers=2`, `npm run build`.
